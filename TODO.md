# Post-Release TODO

- [ ] Accents: é is sent as Ctrl+Shift+U 00e9 Enter, and GNOME's terminal (ptyxis) printed junk instead of é. Survey which apps get it wrong before changing anything. If it's common, type the char directly via zwp_virtual_keyboard_v1 (Sway has it, KDE and GNOME don't) and keep Ctrl+Shift+U as fallback. Idea from Kam1ni/gamepad-osk-no-uinput.
- [ ] KDE Alt+Tab: in a Plasma VM, a quick second Alt+Tab or the next d-pad move comes 0.3-1.5 s late. Cause: input, key sending and drawing share one thread, and SDL_RenderPresent waits on KWin after Alt+Tab. Mostly late, not lost (one run landed on the wrong key). VM draws in software, so try it on real KDE hardware first. Fix is the input thread split below.
- [ ] Extra buttons: DualSense Edge paddles and Fn (BTN_TRIGGER_HAPPY1-4), maybe Elite and Deck back buttons too. Ignored right now, which is fine. Could add names like p1-p4 to the button table so people can map them. Check what xpad sends for Elite paddles first.
- [ ] Split App.Run (app.go, ~500 lines): setup, SDL/Wayland wiring and the main loop are one function over a lot of package globals (KeyGlyphs, PopupHint, isWayland, sockPath...). Pull the loop and show/hide into App methods so they can be unit tested. Big job, do it after Phase 3, not mid-port.
- [ ] Input on its own thread: read the pad, handle actions and send keys off the main thread so a slow frame can't delay a key. Needs a lock on KeyboardState, window/SDL calls queued back to the main thread, and Draw split so Present runs without the lock. Do it with the App.Run split.
- [ ] Idle wakeups (investigate first): hidden, the loop wakes every 16 ms to poll IPC and the pad (app.go ~497). CPU is under 1%, so it's only timer wakeups. Blocking on the pad fd and the socket instead could break combo timing, reconnects and repeat. Look at it during the split, don't change it alone.
